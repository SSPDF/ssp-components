Consolida o CHANGELOG da `1.0.0-rc.1` à `1.0.0-rc.4` e o que as migrações do specto e do viva-flor ensinaram. O CHANGELOG do pacote continua sendo a fonte: leia-o com `--changelog`.

## Ordem dos codemods

Passe as pastas de código do app **escritas no comando** (ex.: `pages components hooks utils lib`), **nunca `.`** (o jscodeshift só ignora `node_modules`, e entraria no `.next`). Não guarde as pastas numa variável: no zsh (padrão do macOS) `$P` não se divide em palavras, e o codemod recebe um caminho só, inexistente, e termina com `0 ok` sem avisar. Rode um de cada vez e olhe o `git diff --stat` entre eles.

```sh
npx @mui/codemod@latest v6.0.0/all pages components
npx @mui/codemod@latest v7.0.0/grid-props pages components
npx @mui/codemod@latest v7.0.0/lab-removed-components pages components      # só se o app importa @mui/lab
npx @mui/codemod@latest v7.0.0/input-label-size-normal-medium pages components
npx @mui/codemod@latest deprecations/all pages components
npx @mui/codemod@latest v9.0.0/system-props pages components

# só se o app importa @mui/x-charts (não há codemod de charts no v7)
npx @mui/x-codemod@latest v8.0.0/charts/preset-safe pages components
npx @mui/x-codemod@latest v9.0.0/charts/preset-safe pages components

# só se o app importa @mui/x-date-pickers (um por major que ele atravessa)
npx @mui/x-codemod@latest v7.0.0/pickers/preset-safe pages components
npx @mui/x-codemod@latest v8.0.0/pickers/preset-safe pages components
npx @mui/x-codemod@latest v9.0.0/pickers/preset-safe pages components
```

Os `@mui/x-codemod` imprimem uma linha `NOC <arquivo>` para cada arquivo sem nada a mudar: é normal.

Confira que cada um termina com `0 errors` e algum `ok` (ou nenhum arquivo a mudar). O `v6.0.0/all` e o `deprecations/all` imprimem `Input Error: You must pass a valid list of files to parse` quando o app não tem arquivos `.css` para os codemods de CSS: é inofensivo.

No specto (30/09/2026) a sequência tocou 12 arquivos: quase tudo foi o `system-props` (props soltas → `sx`), mais o `grid-props` em 3 arquivos e o `deprecations/all` em 1 (`InputProps` → `slotProps.input`). O `system-props` também move `color="text.secondary"` para o `sx` quando reescreve o elemento.

**Formatação:** os codemods reescrevem com aspas duplas, ponto e vírgula e props quebradas em linhas. Se o app tem config de Prettier (`.prettierrc`), rode `npx prettier --write` **só nos arquivos que a migração tocou** e avise o usuário que o diff inclui a formatação desses arquivos (alguns já estavam fora do padrão antes).

Depois: `node SCRIPT --comparar-spreads …` (obrigatório) e o diagnóstico de novo.

## O que os codemods não resolvem

Cada item tem a categoria do diagnóstico que o aponta.

### Layout (silencioso)

- **`{...{ xs, sm, md }}`** (objeto literal só com breakpoints) o codemod do Grid converte certo em `size`: o script não conta como spread perdido.
- **Spreads apagados** (`spread-em-risco`, `--comparar-spreads`). `<Grid item {...props} xs={6}>` vira `<Grid size={6}>`, sem o `{...props}`. No viva-flor, `Field`/`File` perderam o `md` e a tela de detalhes ficou com campos em largura total. Para cada spread perdido, veja o que ele carregava nos usos do componente: se levava props de layout (`md`, `sm`), converta-as em `size`; se levava props que o elemento usa (`onClick`, `sx`, `key` não conta), reponha o spread sem as props de Grid legado. No specto, os dois `Field` (`components/field.tsx` e o de `pages/buscaCPF/[id].tsx`) só recebiam `xs`, já convertido pelo codemod: bastou trocar o `extends GridProps` por `xs?: number`. No viva-flor (`detalhes/field.tsx`, `detalhes/file.tsx`, `file.tsx`, 93 usos com `md`): `interface Props extends Omit<GridProps, 'size'>` com `xs?`/`sm?`/`md?`/`lg?`/`xl?` declarados, `size={{ xs, sm, md, lg, xl }}` e o resto das props espalhado de volta (`{...props}` depois de tirar as larguras).
- **Componente com `interface Props extends GridProps` que usa `xs`/`md`** (`gridprops`): o `GridProps` do MUI 7+ não tem essas props. Declare-as nas props do componente e converta: `size={{ xs: props.xs ?? 12, md: props.md }}`. Não espalhe `xs`/`md` cru no `Grid`.
- **Campos da lib fora de `<Grid container>`**: o `xs`/`md` dos campos da lib (`<Input md={6} />`) vira `size` do Grid v2 e só funciona dentro de um `<Grid container>` do `@mui/material`. **Não** troque containers por `GridLegacy` (o codemod às vezes sugere): lá dentro os campos da lib ficam com largura total.
- **`<Grid direction="column">`** (`grid-direction-column`) não existe mais: use `<Stack>`.
- **`color="text.secondary"`** num `Typography`/`Link` (`cor-caminho-tema`) vira preto no MUI 9. Use `sx={{ color: 'text.secondary' }}` ou os nomes da paleta que a prop aceita (`textPrimary`, `textSecondary`, `primary`, `error`…).

### SSR: `transpilePackages`

Desde a `1.0.0-rc.2` o ESM da lib sai em `.mjs`. Sem `transpilePackages`, o Next carrega a lib como módulo externo no SSR, com o `import` nativo do Node, e o `next build` quebra: `Failed to load external module @ssplib/react-components … ERR_MODULE_NOT_FOUND … dayjs/plugin/customParseFormat` (e, passado esse, `next/image` chega como objeto: erro #130 do React). O specto já transpilava; o viva-flor não (30/09/2026). A correção é no app:

```js
transpilePackages: ['@ssplib/react-components'], // mais o que o app já tinha
```

### Pickers do próprio app (silencioso)

Apps com pickers próprios (o viva-flor tem cópias antigas dos componentes da lib em `components/form/`) passam pelo mesmo que a lib passou (categoria `picker`):

- `value={v ? dayjs(v) : undefined}` → `null`. Com `undefined` o picker nasce não controlado, e o console repete `A component is changing the uncontrolled value state of a picker component to be controlled` a cada campo (29 vezes no cadastro do viva-flor).
- Estilo em `div input`/`input`/`.MuiOutlinedInput-*` não pega mais: o campo é um grupo de seções (`role="spinbutton"`). Use `'& .MuiPickersInputBase-root': { paddingLeft: 2 }` e `'& .MuiPickersInputBase-sectionsContainer': { paddingY: 1.05 }`, como a lib; senão o campo fica mais alto que os outros do formulário.

### Tipos e props

- **Props removidas do `TextField` e afins** (`props-removidas`): `InputProps` → `slotProps.input`, `inputProps` → `slotProps.htmlInput`, `InputLabelProps` → `slotProps.inputLabel`, `FormHelperTextProps` → `slotProps.formHelperText`, `SelectProps` → `slotProps.select`, `PaperProps` → `slotProps.paper`. Vale também para o `Input` da lib. Num `Autocomplete` com `renderInput`, espalhe `...params.slotProps` antes do seu `slotProps` no `TextField`, ou o campo perde o papel de combobox.
- **Ícones `*Outline`** (`icone-outline`, `icone-inexistente`): saíram no icons-material 9. `ErrorOutline` → `ErrorOutlineOutlined`, `DeleteOutline` → `DeleteOutlineOutlined` (mesmo desenho). O `*Outlined` que o TypeScript sugere é **outro** ícone (preenchido).
- **`LoadingButton`** (`lab`): `import { Button } from '@mui/material'` com `loading` e `loadingPosition`. **À mão**: o codemod `v7.0.0/lab-removed-components` não converteu nem no specto nem no viva-flor (`0 ok`).
- **`Select` com `placeholder`**: a prop saiu dos tipos do `Select` no MUI 9, e nunca aparecia na tela (o `Select` não mostra placeholder). Remova.
- **`useState([])` usado como lista de objetos**: no React 19 os tipos inferem `never[]`, e `option.id` não compila. Tipe o estado (`useState<Opcao[]>([])`).
- **`ReactElement` sem parâmetro** (React 19: `props: unknown`) em código que clona filhos (`React.cloneElement(x, { ...x.props, prefix })`, `x.props.name`): declare o formato, ex. `ReactElement<{ name?: string; children?: ReactNode }>`. No viva-flor, `Stepper` e `StepperBlock`.
- **React 19** (`jsx-global`, `useref-sem-valor`, `defaultprops`, `react-removido`): `JSX.Element` → `React.JSX.Element`; `useRef<T>()` → `useRef<T>(null)`; `defaultProps` de função → default nos parâmetros; ref de callback não retorna nada além de uma função de cleanup; `ReactElement` sem parâmetro tem `props: unknown`.
- **`@mui/x-charts` 9** (`x-charts`): `highlightScope: { faded, highlighted }` → `{ fade, highlight }`; `itemMarkWidth`/`itemMarkHeight`/`labelStyle`/`padding` da legenda saíram (use o `sx` da legenda, classe `.MuiChartsLegend-mark`). O aviso de dev `An input selector returned a different result when passed same arguments` vem do x-charts e não afeta a tela.
- **`react-toastify` 11** (`toastify-css`): o CSS é injetado; `ReactToastify.min.css` não existe mais (o import de `react-toastify/dist/ReactToastify.css` pode ficar).

### Testes do app

- Pickers (`DatePicker`, `GenericDatePicker`, `TimePicker`) não têm `<input>` de texto: são `getByRole('group', { name: title })` com seções `spinbutton`.
- `Switch` tem `role="switch"`.
- `Input type='email'` renderiza `<input type='text' inputmode='email'>`.
- Campos da lib pelo papel e pelo `title`: `getByRole('textbox' | 'combobox', { name: title })`; `Radio` é `radiogroup`/`radio`.

## Requisitos de ambiente (desde a `0.4.0`)

- Node ≥ 22 para instalar e buildar.
- `KeycloakAuthProvider` só funciona em HTTPS ou `localhost` (Web Crypto). Acesso por IP em `http://` na rede interna falha com `Web Crypto API is not available`.
- `public/silent-check-sso.html` servido pelo app, e o `basePath` do provider igual ao do `next.config.js`.
